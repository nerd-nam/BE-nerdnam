# 06. API ↔ AI 계약 — BE 쪽 구현 규칙

> **계약 파일이 생겼습니다 (2026-10-23):** `SPEC-nerdnam/contracts/api-ai.openapi.yaml` (C-04 v0.2.0, SPEC PR #39, AI 레포의 `/openapi.json`에서 내보냄). 요청·응답 **모양은 그 파일이 기준**입니다.
> 이 문서는 계약에 담기지 않는 **BE 쪽 규칙**(오류 분류·재시도·시간 제한·입력 규칙을 막는 곳·개발용 스텁)만 남깁니다.
> 기준: 기획서 5.4·5.5(AI 서버 공통 규칙, v1.18·v1.20·v1.23)·5.6, ADR-0001(GPU 서빙·임베딩 확정), ADR-0003(`/gap-guide`)

## 계약 대조 결과 (2026-10-23)

C-04 v0.2.0과 BE 요청·응답 타입(`infra.ai`)을 `ApiAiContractTest`로 대조합니다. 탭별 `content`는 Map으로 받아 공통 예시 5개를 손실 없이 읽고 쓰는지 확인합니다. AI 서버의 실제 생성 품질이나 C-03 웹 응답 보강은 이 테스트의 범위가 아닙니다.

| 계약 | BE 구현 |
| --- | --- |
| `RestructureRequest.mode` = `initial`/`split`/`episode`, `source_text` 필수 | `RestructureRequest.MODE_*`. 첫 나누기 `initial`, 다시 나누기 `split`(피드백 필수), 사례 고치기 `episode` |
| `GuideRequest.tab` = `motive`/`intro`/`portfolio`/`career`/`image`, `requirements` 필수 | `GuideTab.aiName()` = 웹 주소 이름. 작업의 `mode`·`lock_scope` 도 같은 값 |
| `GuideResponse` = `content`·`cited_chunk_ids`·`model`·`prompt_version` (JSON 하나, SSE 없음) | `GuideCall.Result` 그대로. 받는 쪽은 SSE 로 와도 해석한다(`ServerSentEvents`) |
| `EmbedRequest.purpose` = `document`/`query` | `EmbedPurpose` 를 소문자로 보낸다 |
| `MatchRequirement.type` = `required`/`preferred`, `Candidate.chunk_type` = `skill`/`career`/`project_summary`/`episode` | 둘 다 소문자로 보낸다 |
| `MatchResult.verdict` = `met`/`partial`/`unmet` | 소문자로 읽고, 모르는 값은 미충족으로 본다 |
| `GapRequirement.verdict` = `partial`/`unmet` (충족 없음) | `MET` 요건은 보내지 않는다 |
| `EmbedResponse` = `embedding_model`·`dim`·`vectors` 필수 | `dim` 과 벡터 길이가 다르면 `AI_ERROR` |

BE-16 계약 테스트·CI를 구현했습니다. `ApiAiContractTest` 46개가 실제 Jackson JSON 필드·필수 목록·코드의 enum 값과 계약을 비교합니다. 필수 목록은 합의한 값을 별도로 고정합니다(record에는 필수 여부 표시가 없음). 실제 누락 응답을 클라이언트가 거부하는지 검사하는 것은 아닙니다.

계약 복사본은 `src/test/resources/contracts/`에 있습니다. 옆에 SPEC 체크아웃이 있으면 원본과도 비교하고, 없는 CI에서는 원본 비교 2개만 건너뜁니다. main push·PR에서 전체 테스트를 실행하며, 실패하면 보고서를 보관합니다. 갱신 절차와 검증 결과는 docs/07 작업 A에 있습니다.

## 공통

| 항목 | 정한 것 |
| --- | --- |
| JSON 이름 | snake_case (`source_spans`, `min_years`, `prompt_version`) |
| 사용자 정보 | 보내지 않는다. 청크는 id 와 텍스트만 (기획서 5.5) |
| 모델 기록 | 모든 생성 응답에 `model`, `prompt_version`을 담는다. API 가 결과와 `ai_call_log`에 저장한다. `/embed`는 프롬프트가 없어 `embedding_model`만 |
| 연결 시간 제한 | 모두 2초. GPU 서버가 꺼져 있으면 빨리 실패한다 (ADR-0001, `nerdnam.ai.connect-timeout`) |
| 읽기 시간 제한 | 엔드포인트마다 다르다 (아래 표, `nerdnam.ai.read-timeouts.*`) |
| 상태 확인 | `GET /health` → `{"status": "ok", "models": {"llm": "ready", "embedding": "ready"}}` |

### 읽기 시간 제한 (기획서 5.5, 성능 목표의 약 2배)

| 엔드포인트 | 제한 | 근거 |
| --- | --- | --- |
| `/health` | 2초 | |
| `/embed` | 10초 | |
| `/requirements/extract` | 20초 | 리포트 20초 안의 한 단계 |
| `/restructure` | 30초 | 재구성 목표 15초 |
| `/match` | 30초 | 리포트 목표 20초 |
| `/gap-guide` | 20초 | 실패하면 기본 문구로 대신한다 (ADR-0003) |
| `/guide` | 120초 | 작성 방향 목표 60초 |

부하 테스트 결과로 조정합니다. 켠 직후 첫 요청은 20~24초까지 걸렸습니다.

### 입력 규칙 (기획서 5.5, v1.20) — 어기면 AI 서버가 422

422 는 다시 시도하지 않으므로(아래 표) **API 가 부르기 전에 막습니다.**

| 엔드포인트 | 규칙 | API 가 막는 곳 |
| --- | --- | --- |
| `/restructure` | `mode` = `initial`(첫 나누기, 원문 수정 후 재구성 포함) / `split`(다시 나누기) / `episode`(사례 수정 요청·확인 답변). `split` 은 비어 있지 않은 `feedback` 필수 | `RestructureRequest.MODE_*`, `Project.checkCanResplit()`(피드백 없으면 400) |
| `/gap-guide` | `verdict` 가 `partial`·`unmet` 인 요건만 (ADR-0003) | `FitAnalysisPipeline.withGapGuides()`(`MET` 제외) |
| `/guide` | `tab` = `motive` / `intro` / `portfolio` / `career` / `image` (웹 주소와 같은 값) | `GuideTab.aiName()` |
| 공통 | 목록 입력(`items`, `requirements`, `lines`)은 1개 이상 | 공고는 필수 요건 1개 이상(`JobPosting.violations()`), 청크 묶음은 비어 있으면 호출 안 함(`ChunkEmbedder`) |

개발용 스텁(`StubAiServerClient`)도 같은 규칙을 검사해 `AI_ERROR` 로 실패시킵니다 — 잘못된 입력을 로컬에서 바로 잡기 위해서입니다 (`StubAiServerClientTest`).

### GPU 서버 실행 (기획서 5.5, v1.20)

- AI 서버 포트는 `8000` (`nerdnam.ai.base-url`). API 서버만 접근합니다(보안 그룹). vLLM 은 AI 서버 안에서만 씁니다.
- AI 서버 환경변수 `AI_MODE`: `stub`(기본, GPU 없이 가짜 응답) / `real`. API 는 `stub` 모드 AI 서버를 그대로 쓸 수 있습니다 — 이때 `/embed` 응답의 `embedding_model` 이 `"stub"` 이라 벡터를 저장하지 않습니다.
- 켠 뒤 `/health` 가 모두 `ready` 가 되기까지 몇 분, 첫 실행은 모델 다운로드로 최대 15분까지 걸립니다. 그동안 요청은 503 → `GPU_UNAVAILABLE` 입니다. "임베딩 대기" 청크 재처리는 `/health` 가 준비됐을 때만 합니다.

### 실패 구분과 다시 시도 (기획서 5.5 D-7)

`failureCode`는 AI 작업(`ai_job`)에 그대로 저장하고, 웹이 이 값으로 화면 문구를 고릅니다 (C-02 공통 3).

| AI 서버 응답 | 뜻 | `failureCode` | 다시 시도 |
| --- | --- | --- | --- |
| 연결 실패·연결 시간 초과 | GPU 서버가 꺼져 있음 | `GPU_UNAVAILABLE` | 1회 |
| 503 | 모델 로딩 중이거나 로딩 실패 | `GPU_UNAVAILABLE` | 1회 |
| 4xx (422 요청 형식 오류 등) | API 쪽 문제 | `AI_ERROR` | 안 함 |
| 그 밖의 5xx | AI 서버 오류 | `AI_ERROR` | 1회 |
| 읽기 시간 초과 | 생성이 시간 안에 끝나지 않음 | `TIMEOUT` | **안 함** — 같은 요청을 다시 보내면 GPU 부하만 두 배가 된다 |

구현 주의: 읽기 시간 초과는 응답을 읽는 중에 터지므로 Spring 이 `ResourceAccessException` 이 아닌 평범한
`RestClientException`으로 감싸 올릴 수 있습니다. 그래서 `HttpAiServerClient.classify()`는 원인 사슬을 끝까지 따라가
`SocketTimeoutException`을 찾습니다 (`HttpAiServerClientTest`로 고정).

**GPU 가 꺼져 있을 때 (ADR-0001 결정, 2026-10-23):** 생성 작업(재구성·분석·작성 방향)은 **바로 실패**시킨다 — 대기시키지 않는다. 작업 상태에 `failure_code = GPU_UNAVAILABLE` 을 남기고 웹이 안내한다. 임베딩 청크만 "임베딩 대기"로 두고 `/health` 가 준비되면 재처리한다. (켠 뒤 준비까지 몇 분, 첫 실행은 최대 15분이라 기다리게 하지 않는다.)

### `GET /health` 의 모델 상태

| `models` 값 | 뜻 |
| --- | --- |
| `stub` | 가짜 응답 모드 (GPU 없이 개발할 때) |
| `loading` | 모델 로딩·예열 중 (켠 직후 몇 분) |
| `ready` | 사용 가능 |
| `error` | 로딩 실패 (AI 서버 재시작 필요) |

**모든 모델이 `ready`일 때만** 준비된 것으로 보고 "임베딩 대기" 청크를 다시 처리합니다 (기획서 8장). 연결이 안 되면 꺼진 것으로 봅니다.

### 가짜 응답(stub) 처리

AI 서버를 `stub` 모드로 띄우면 모든 엔드포인트가 형식만 같은 가짜 응답을 돌려줍니다. API 서버 자체의 개발용 스텁
(`nerdnam.ai.stub=true`, `StubAiServerClient`)과는 별개입니다.

| 엔드포인트 | 가짜 응답 표시 | API 처리 |
| --- | --- | --- |
| `/embed` | `embedding_model`이 `"stub"` | 벡터를 저장하지 않고 청크를 "임베딩 대기"로 둔다 (`ChunkEmbedder`) |
| LLM 엔드포인트 | `prompt_version`이 `"stub"` | 개발용 결과로만 쓴다 |
| `/health` | `models` 값이 `"stub"` | 준비된 것으로 보지 않는다 |

## POST /embed

```jsonc
// 요청 — purpose: document(청크 등록) / query(요건 검색)
{"purpose": "document",
 "items": [{"text": "기술: Redis\n카테고리: DB ...", "title": "Redis"}]}
// 응답 — vectors 는 items 순서, 768차원 (ADR-0001 확정), 길이 1로 정규화 (코사인 거리)
{"embedding_model": "google/embeddinggemma-2@914f7f89142e33e77833254d9c9b90c3cef7303b:768",
 "dim": 768,
 "vectors": [[0.01, ...]]}
```

- `items[].text`는 필수, `items[].title`은 선택입니다. `document`면 청크 제목(`rag.chunk.title`)을 같이 보냅니다 — 검색 품질이 좋아집니다. 요건 검색(`query`)은 제목을 쓰지 않습니다.
- 접두어(`task: search result | query:` 등)는 AI 서버가 붙입니다. API 는 원래 텍스트만 보냅니다.
- 벡터 개수가 `items` 수와 다르거나, 벡터 길이가 응답의 `dim` 과 다르면 `AI_ERROR`.
- `embedding_model`은 청크마다 저장해 모델을 바꿀 때 재임베딩 대상을 찾는 데 씁니다 (기획서 4.4). `"stub"`이면 저장하지 않습니다.

## POST /restructure (P1)

```json
{
  "mode": "initial",                     // initial = 첫 나누기, split = 다시 나누기(피드백 필수), episode = 사례 하나 고치기
  "title": "결제 승인 API 성능 개선",
  "source_text": "원문...\n\n질문: ...\n답변: ...",   // 원문 + 보충 답변. source_spans 의 기준
  "skills": ["Spring Boot", "Redis"],    // 프로젝트 사용 기술 (표준 이름). 사례 skills 는 이 안에서만
  "previous_episodes": [ {사례} ],        // 재등록 중이면 이전 확정 사례 (맥락)
  "current_episodes": [ {사례} ],         // 다시 나누기면 지금 검토 중인 사례 (피드백의 대상)
  "target_episode": {사례} | null,        // episode 모드에서 고칠 사례
  "feedback": "두 사례를 합쳐 줘" | null,  // 다시 나누기·수정 요청
  "answer": {"question": "...", "answer": "..."} | null   // 확인 질문 답변 (episode 모드)
}
```

사례 모양 (기획서 4.3):

```json
{
  "title": "결제 승인 응답 지연 개선", "role": "백엔드 리드 (팀 4명)",
  "problem": "...", "solution": "...", "result": "...",
  "skills": ["Spring Boot", "Redis"],
  "metrics": [{"name": "평균 응답시간", "before": "1.2s", "after": "0.3s", "source": "raw_text"}],
  "source_spans": [[0, 182]],
  "clarifications": [{"key": "q1", "field": "result", "question": "응답 속도 개선 수치가 있나요?", "example": "예: 1.2초 → 0.3초"}]
}
```

응답: `{"episodes": [사례...], "model": "...", "prompt_version": "..."}` (episode 모드는 1개)

API 쪽 처리 (AI 가 알아 둘 것):
- `skills` 중 프로젝트 사용 기술에 없는 것은 버린다 (P9). 대소문자·공백만 달라도 같은 것으로 본다.
- `source_spans` 중 `source_text` 밖이거나 모양이 틀린 것은 버린다.
- `clarifications[].key`가 없거나 겹치면 API 가 `q1, q2…`를 붙인다. 사용자는 이 key 로 답하거나 뺀다.
- 답한 질문(`answer.question`)을 응답에 다시 넣어도 API 가 뺀다.
- 사례가 0개면 반영하지 않고 작업 실패(`AI_ERROR`).

## POST /requirements/extract (P2)

```json
// 요청 — type: required / preferred
{"lines": [{"id": 11, "type": "required", "text": "Java/Spring 기반 개발 3년 이상"}]}
// 응답 — 문구는 돌려주지 않는다(바꾸지 않으므로). 기술명은 원문 그대로, 정규화는 API 가 한다
{"lines": [{"id": 11, "skills_raw": ["Java", "Spring"], "min_years": 3}], "model": "...", "prompt_version": "..."}
```

## POST /match (P3)

```json
{"requirements": [{
  "id": 11, "type": "required", "text": "...", "skills": ["Java", "Spring"], "min_years": 3,
  "candidates": [{"chunk_id": 501, "chunk_type": "episode", "text": "프로젝트: ...\n사례: ..."}]   // 요건별 최대 20개
}]}
```

응답: `{"results": [{"id": 11, "verdict": "met", "evidence_chunk_ids": [501, 503], "reason": "..."}], "model": "...", "prompt_version": "..."}`

- `verdict`: `met` / `partial` / `unmet`. 모르는 값은 미충족으로 본다.
- `evidence_chunk_ids`는 그 요건의 후보 안의 것만 인정한다 (최대 5개). 근거 없이 `met`·`partial`이면 미충족으로 본다.
- 결과가 빠진 요건은 미충족 + "판정 결과를 받지 못했어요."
- 연차 규칙 판정은 API 가 따로 하고, 둘이 다르면 낮은 쪽 (D-5).

## POST /gap-guide (P6, ADR-0003)

```json
{"requirements": [{"id": 13, "type": "preferred", "text": "Kubernetes 운영 경험", "verdict": "unmet",
                   "adjacent": [{"chunk_id": 502, "chunk_type": "skill", "text": "..."}]}],   // 근거로 뽑히지 못한 후보 최대 5개
 "tasks": ["결제 승인 시스템 개발"]}
```

응답: `{"guides": [{"id": 13, "advice": "...", "avoid": "...", "cited_chunk_ids": [502]}], "model": "...", "prompt_version": "..."}`

- 미충족·부분 충족 요건만 보낸다. `cited_chunk_ids`는 그 요건의 `adjacent` 안의 것만 남긴다.
- 실패하거나 요건이 빠지면 API 가 판정별 기본 문구로 저장하고 분석은 완료한다 (`gap_source = FALLBACK`).

## POST /guide (P4·P5, SSE)

```json
{"tab": "motive",           // motive / intro / portfolio / career / image (웹 주소의 탭 이름과 같다)
 "company": "OO페이", "position": "백엔드 개발자", "company_intro": "...", "tasks": ["..."],
 "requirements": [{"id": 11, "type": "required", "text": "...", "verdict": "met", "reason": "...",
                   "evidence": [{"chunk_id": 501, "chunk_type": "episode", "text": "..."}],
                   "gap_guide": {"advice": "...", "avoid": "..."} | null}],
 "feedback": "더 짧게" | null}
```

응답은 SSE. API 는 끝까지 받아 모은 뒤 **마지막 `event: result`의 data**를 결과로 쓴다. `event: error`가 있으면 실패. 진행 이벤트(`event: delta` 등)는 무시한다. SSE 대신 JSON 한 덩어리로 줘도 받는다.

```text
event: delta
data: {"text": "..."}

event: result
data: {"content": {...탭 내용...}, "cited_chunk_ids": [501], "model": "...", "prompt_version": "..."}
```

- `content`의 모양은 탭마다 AI 계약이 정한다. API 는 jsonb 로 통째로 저장한다.
- API 가 저장 전에 하는 일: `cited_chunk_ids`와 `content` 안의 모든 `sources` 숫자 목록에서 이 분석의 근거·갭 인용 밖의 청크를 뺀다. 포트폴리오 `pages`는 `order` 순으로 정렬하고 `kind`가 `cover/text/diagram/chart`가 아니면 `text`.
