## 주요 구현을 검토할 때

- 삭제 전 `ProjectDeleting` 이벤트로 과거 작성 방향의 인용 이름을 보완한다. 프로젝트 삭제·flush 뒤 `ProjectDeleted`에서 리포트 근거 원문을 이름으로 바꾸고 검색 청크를 지운다. 이벤트는 동기식이며 같은 트랜잭션이다.
- V5는 테이블 추가 없이 `match_evidence.source_deleted`, `writing_guide.citation_snapshots`를 추가한다. 적용된 V1~V4를 고치지 않았다.
- 새 작성 방향은 AI 호출 전 이름·원본 id만 `CitationSnapshot`으로 저장한다. 조회 시 공개 프로젝트 조회로 현재 삭제·재등록 여부를 붙인다. 삭제된 근거는 다음 AI 요청에서 제외한다.
- C-03은 C-04의 `content`를 그대로 보존한다. `sources`의 청크 id는 `citations[].chunkId`로, `coverage.requirement_id`는 리포트의 `matches[].requirementId`로 연결한다. 정확한 FE 연결 규칙은 `docs/08-웹-API-계약.md`.
- 계약 테스트는 JSON Schema 전체 검증기가 아니다. 실제 API 동작은 별도의 API 테스트가 검증한다. 필요한 검증이 부족하면 JUnit 테스트로 추가한다.
- `ConsentCsrfTest`는 다른 Spring 컨텍스트를 사용한다. 기존 테스트의 `.with(csrf())`가 공유 필터의 저장소를 바꾸기 때문에 실제 쿠키 검증과 분리했다. 합치지 않는다.
