## 작업 A — 계약 테스트와 CI (BE-16) · **먼저 하세요**

### 왜 지금인가

막고 있던 것이 2026-10-23 에 둘 다 생겼습니다.

- `../SPEC-nerdnam/contracts/api-ai.openapi.yaml` — C-04 계약 v0.1
- `../SPEC-nerdnam/fixtures/` — 공통 예시 데이터 (`chunks.json`, `jd.json`, `match.json`, `profile.json`, `projects.json`)

지금은 사람이 눈으로 대조했습니다(`docs/06` "계약 대조 결과"). **계약이 바뀌면 조용히 깨지므로 테스트로 고정해야 합니다.**

### 목표 (완료 기준)

1. `./gradlew test` 에 **계약 대조 테스트**가 포함된다. 계약의 필드 이름·필수 여부·enum 값이 BE 의 `infra.ai` 타입과 다르면 **실패**한다.
2. GitHub Actions 가 push·PR 마다 `./gradlew test` 를 돌린다.

### 단계

**A-1. 계약 파일을 테스트 자원으로 가져오기**

계약은 다른 레포에 있어서 CI 가 읽을 수 없습니다. `src/test/resources/contracts/api-ai.openapi.yaml` 로 **복사**하고, 파일 맨 위에 출처와 복사 시점을 주석으로 남기세요.

```yaml
# SPEC-nerdnam/contracts/api-ai.openapi.yaml 에서 복사 (C-04 v0.1, 2026-10-23)
# 계약이 바뀌면 다시 복사한다. 대조는 ApiAiContractTest 가 한다.
```

> 서브모듈·CI 체크아웃도 방법이지만, 레포가 비공개라 토큰이 필요하고 관리가 늘어납니다. 복사 + "다시 복사한다" 주석이 지금 규모에 맞습니다. 복사본이 낡는 것이 걱정되면, SPEC 체크아웃이 옆에 있을 때만 두 파일을 비교하는 테스트를 추가하세요(없으면 건너뛰기).

**A-2. 계약 대조 테스트** (`src/test/java/com/nerdnam/infra/ai/ApiAiContractTest.java`)

YAML 을 읽어 스키마와 BE 타입을 맞춥니다. Spring 을 띄우지 않는 단위 테스트로 만드세요 (빠릅니다).

- YAML 읽기: `tools.jackson.dataformat:jackson-dataformat-yaml` 을 `testImplementation` 으로 추가 (Jackson 3 입니다. 버전은 Boot BOM 이 정합니다)
- 비교 방법: BE 의 요청·응답 record 를 **실제 Jackson 매퍼로 직렬화**해 JSON 키를 뽑고, 계약 스키마의 `properties` 키와 비교합니다. record 필드를 리플렉션으로 읽으면 `@JsonNaming(SnakeCase)` 적용 결과를 놓칩니다.
- 꼭 고정할 것:
  - `RestructureRequest.mode` = `initial` / `split` / `episode` (상수 `RestructureRequest.MODE_*`)
  - `GuideRequest.tab` = `motive` / `intro` / `portfolio` / `career` / `image` (`GuideTab.aiName()` 전체)
  - `EmbedRequest.purpose` = `document` / `query`
  - `MatchRequirement.type`·`GapRequirement.type` = `required` / `preferred`
  - `MatchResult.verdict` = `met` / `partial` / `unmet`, `GapRequirement.verdict` = `partial` / `unmet` (충족 없음)
  - `Candidate.chunk_type` = `skill` / `career` / `project_summary` / `episode` (`EvidenceSourceType` 전체)
  - 필수 필드: `EmbedResponse` 의 `embedding_model`·`dim`·`vectors`, `GuideResponse` 의 `content`·`cited_chunk_ids`·`model`·`prompt_version`
- **enum 값은 코드에서 뽑아 비교하세요.** 테스트에 문자열을 손으로 적으면 코드가 바뀔 때 같이 안 바뀝니다. 예: `Arrays.stream(GuideTab.values()).map(GuideTab::aiName)` ↔ 계약의 `enum` 목록.

**A-3. GitHub Actions** (`.github/workflows/test.yml`)

- `ubuntu-latest` 에는 Docker 가 있어 **Testcontainers 가 그대로 됩니다.** 서비스 컨테이너를 따로 선언하지 말고 `./gradlew test` 만 돌리세요 (`NERDNAM_TEST_USE_LOCAL_DB` 는 쓰지 않습니다).
- JDK 21 (`actions/setup-java`, `temurin`), Gradle 캐시(`gradle/actions/setup-gradle`).
- 한글 테스트 이름 때문에 `LANG=C.UTF-8` 을 환경 변수로 주세요 (`CLAUDE.md` 테스트 절 참고).
- 트리거: `push` (main) + `pull_request`.
- 실패 시 테스트 리포트를 올리면(`actions/upload-artifact`) 디버깅이 편합니다.

### 하지 말 것

- 계약에 맞추려고 **BE 구현을 바꾸지 마세요.** 지금은 일치합니다(`docs/06` 대조 표). 테스트가 실패하면 테스트가 틀렸는지 먼저 의심하고, 정말 계약이 다르면 **고치기 전에 이슈로 올리세요** (AI 레포).
- 계약에 없는 것을 테스트로 고정하지 마세요. `/guide` 의 `content` 모양은 **아직 정하는 중**입니다 (AI 레포 #9).

## 작업 B — 실제 AI 서버에 붙여 보기

### 지금 할 수 있는 것

AI 레포가 **로컬에 있습니다**: `../AI-nerdnam` (FastAPI, `AI-01` 완료 — 모든 엔드포인트가 형식만 같은 **가짜 응답**을 줍니다).

```bash
cd ../AI-nerdnam && uv sync && uv run uvicorn app.main:app --port 8000   # 문서: localhost:8000/docs
cd ../BE-nerdnam && ./gradlew bootRun --args='--nerdnam.ai.stub=false'
```

### 꼭 알아야 할 함정 — 가짜 응답 모드에서는 검색이 비어 있습니다

AI 레포의 `/embed` 는 `embedding_model: "stub"` 을 돌려줍니다 (`app/routers/embed.py` 의 TODO(AI-03)). BE 는 그 값이면 **벡터를 저장하지 않고 청크를 "임베딩 대기"로 둡니다** (기획서 v1.18 규칙, 의도된 동작).

그래서 이 상태로는:

| 확인할 수 있는 것 | 확인할 수 없는 것 |
| --- | --- |
| 요청·응답 형식이 맞는지 (계약 대조의 실물 확인) | 검색 품질·판정 정확도 |
| 오류·타임아웃 처리, 작업 상태 전이 | 적합도 리포트의 근거 (벡터가 없어 후보가 비고 전부 "미충족"으로 나옵니다 — **버그가 아닙니다**) |
| 재구성 전체 흐름, 작성 방향 탭 생성 | 20초·15초 같은 성능 목표 (GPU 서버 필요) |

진짜 모델로 보려면 기획서 v1.24 의 Mac 방법(`llama-server` 로 Qwen3.5-4B, `AI_MODE=real`)을 쓰세요. 그래도 **품질·응답 시간은 GPU 서버에서 재야 합니다.**

### 목표 (완료 기준)

1. 스텁이 아닌 실제 AI 서버로 **전체 흐름이 끝까지 돈다**: 프로젝트 등록 → 재구성 → 사례 확정 → 공고 입력 → 분석 → 리포트 → 작성 방향 탭 1개.
2. 어긋난 곳이 있으면 `infra.ai` **한 패키지 안에서** 고친다 (다른 모듈은 AI 응답 모양을 모릅니다).
3. 결과를 `docs/04` 묶음 1 "9번 실제 AI 서버 연결"에 적는다. 읽기 시간 제한(`nerdnam.ai.read-timeouts.*`)은 실측이 가능할 때 조정하고, 가짜 응답 모드의 숫자는 의미가 없으니 적지 마세요.

### 확인하면 좋은 것 (AI 쪽에 알릴 거리)

- AI 레포 `app/config.py` 의 `EMBED_MODEL` 기본값이 `google/embeddinggemma-2@unpinned:768` 입니다. ADR-0001 이 revision `914f7f89142e33e77833254d9c9b90c3cef7303b` 로 **확정**됐으니 고정값으로 바뀌어야 합니다. 발견하면 AI 레포 이슈로 올리세요 (고치지는 마세요 — 다른 담당 레포입니다).
- `LLM_MODEL` 기본값이 `Qwen/Qwen3.5-9B` 인데 ADR-0001 결정은 **4B** 입니다. 같이 알리세요.

## 작업 C — Redis 결과 캐시 (**사용자 지시를 받은 뒤에**)

설계는 `docs/04` 묶음 3 "결과 캐시는 무엇을 캐시할까"에 적혀 있습니다. 요약:

- 화면에 보이는 결과는 이미 DB 에 있고, 재분석은 "**새로 쌓는다**"로 확정됐습니다(기획서 v1.25). 그래서 **분석 결과를 캐시해 재사용하면 안 됩니다** — 분석일이 안 바뀌어 화면과 어긋납니다.
- 대신 **AI 호출 단계만** 입력 해시로 캐시합니다. 실익은 **실패 후 다시 시도** — 요건 추출은 성공했는데 판정에서 GPU 가 꺼져 실패하면, 다시 시도할 때 성공한 단계를 또 부르지 않습니다.
- 뜻이 분명한(같은 입력 → 같은 출력) `/embed`(query)·`/requirements/extract` 만 캐시하고, 판정·생성(`/match`·`/gap-guide`·`/guide`)은 캐시하지 않습니다.
- 자리는 `infra.ai` 의 감싸기 하나 — `RecordingAiServerClient` 와 같은 자리입니다.

**이 작업은 아직 "진행해"를 받지 않았습니다.** 먼저 사용자에게 확인하세요.
