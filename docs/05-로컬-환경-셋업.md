# 05. 로컬 환경 셋업 (macOS)

> 이 레포의 기술 구성: **Java 21 · Spring Boot 4.1.1 · Gradle 9.8.1(Kotlin DSL) · Spring Data JPA(Hibernate 7) · Flyway · PostgreSQL 17 + pgvector · Testcontainers 2 · Lombok**
> 버전은 2026-10-21 기준 최신 안정판입니다. Spring Boot 4.0.x의 무상 지원은 2026년 12월에 끝나므로 4.1로 시작합니다.

## 1. 설치

터미널에서 순서대로 실행합니다. Homebrew가 없다면 <https://brew.sh> 의 한 줄 명령으로 먼저 설치하세요.

```bash
# 1) JDK 21 (Eclipse Temurin)
brew install --cask temurin@21
java -version            # openjdk version "21.x" 가 보이면 성공

# 2) Docker — Docker Desktop 또는 OrbStack(가볍고 빠름) 중 하나
brew install --cask docker      # 또는: brew install --cask orbstack
# 설치 후 앱을 한 번 실행해 두어야 docker 명령이 동작합니다
docker version

# 3) IntelliJ IDEA (Community 무료 / Ultimate 는 Spring·DB 도구 포함)
brew install --cask intellij-idea-ce
```

> Gradle은 설치하지 않습니다. 레포의 `./gradlew`(Gradle Wrapper)가 맞는 버전을 자동으로 내려받습니다.
> Java 버전을 여러 개 쓸 예정이면 SDKMAN(<https://sdkman.io>)으로 관리해도 됩니다.

## 2. 처음 실행

```bash
cd ~/project/nerdnam/BE-nerdnam

# 1) DB(PostgreSQL+pgvector)와 Redis 띄우기
docker compose up -d
docker compose ps                 # nerdnam-postgres 가 healthy 인지 확인

# 2) 테스트 — 처음에는 의존성·Gradle 다운로드로 몇 분 걸립니다
./gradlew test

# 3) 서버 실행 (기본 프로필 local)
./gradlew bootRun
# 다른 터미널에서
curl http://localhost:8080/actuator/health      # {"status":"UP"}
```

앱이 시작될 때 Flyway가 `src/main/resources/db/migration/`의 V1부터 차례로 적용해 테이블을 만듭니다. 처음 띄우면 로그에 `Successfully applied 4 migrations`(V1~V4)가 보입니다. 이미 V1~V3가 있는 DB면 V4만 적용됩니다.

### 로컬에서 로그인 없이 부르기

local 프로필은 `nerdnam.auth.mode: header`라서 로그인 대신 `X-Member-Id` 헤더로 회원을 고릅니다. 로컬 DB에는 1번 회원이 들어 있습니다. AI 서버도 스텁(`nerdnam.ai.stub: true`)이라 GPU 없이 전체 흐름을 돌려 볼 수 있습니다.

AI 서버(`nerdnam-ai`)를 띄워 붙여 보려면 `nerdnam.ai.stub: false` + `nerdnam.ai.base-url: http://localhost:8000`(AI 서버 포트는 8000)으로 둡니다. AI 서버 쪽 환경변수 `AI_MODE`가 `stub`이면 GPU 없이도 돌지만 `/embed` 응답의 `embedding_model`이 `"stub"`이라 벡터는 저장되지 않습니다. GPU 서버는 켠 뒤 `/health`가 모두 `ready`가 되기까지 몇 분(첫 실행은 모델 다운로드로 최대 15분) 걸리고, 그동안 요청은 `GPU_UNAVAILABLE`로 실패합니다 (기획서 5.5 v1.20, `docs/06-AI-계약-초안.md`).

```bash
curl -H 'X-Member-Id: 1' localhost:8080/api/me
```

### 소셜 로그인을 켜 보려면

`nerdnam.auth.mode`를 `session`으로 바꾸고(예: `--nerdnam.auth.mode=session`), 환경 변수로 OAuth 클라이언트를 넣습니다. 리디렉션 주소는 `http://localhost:8080/login/oauth2/code/google`(카카오는 `.../kakao`)로 각 개발자 콘솔에 등록합니다.

```bash
export GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... KAKAO_CLIENT_ID=... KAKAO_CLIENT_SECRET=...
./gradlew bootRun --args='--nerdnam.auth.mode=session'
# 브라우저에서 http://localhost:8080/oauth2/authorization/google
```

## 3. IntelliJ 설정

1. **Open** → `BE-nerdnam` 폴더 선택 → "Gradle 프로젝트로 열기"를 허용합니다.
2. **Settings → Build, Execution, Deployment → Build Tools → Gradle** → *Gradle JVM*을 `temurin-21`로.
3. **Settings → Build → Compiler → Annotation Processors** → *Enable annotation processing* 체크 (Lombok용. 보통 자동으로 켜짐).
4. `NerdnamApplication`의 ▶ 버튼으로 실행하거나, Gradle 창의 `bootRun`을 실행합니다.
5. 테스트는 클래스·메서드 옆 ▶ 버튼으로 하나씩 돌릴 수 있습니다.

## 4. DB 들여다보기

```bash
# 컨테이너 안의 psql
docker exec -it nerdnam-postgres psql -U nerdnam -d nerdnam

\dn                      -- 스키마 목록 (app, rag)
\dt app.*                -- app 스키마 테이블
\d app.project           -- 테이블 구조
SELECT name, category FROM app.skill ORDER BY category, name;
\q
```

GUI가 편하면 IntelliJ Ultimate의 Database 창, DBeaver, TablePlus 중 하나로 `localhost:5432 / nerdnam / nerdnam / nerdnam`에 접속합니다.

## 5. 자주 쓰는 명령

| 하고 싶은 것 | 명령 |
| --- | --- |
| 서버 실행 | `./gradlew bootRun` |
| 전체 테스트 | `./gradlew test` (결과 보고서: `build/reports/tests/test/index.html`) |
| 테스트 하나만 | `./gradlew test --tests "com.nerdnam.skill.domain.SkillNameKeyTest"` |
| Docker 없이 테스트 | `NERDNAM_TEST_USE_LOCAL_DB=true ./gradlew test` — 컨테이너 대신 `localhost:5432/nerdnam`(pgvector 설치된 PostgreSQL)에 붙는다. 테스트는 회원을 새로 만들어 쓰므로 개발 DB 데이터와 섞이지 않는다 |
| 빌드(jar) | `./gradlew build` → `build/libs/nerdnam-api-0.0.1-SNAPSHOT.jar` |
| 의존성 목록 | `./gradlew dependencies --configuration runtimeClasspath` |
| DB·Redis 켜기 / 끄기 | `docker compose up -d` / `docker compose down` |
| **로컬 DB 초기화** (마이그레이션을 처음부터 다시) | `docker compose down -v && docker compose up -d` |

## 6. 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `Connection refused localhost:5432` | DB 컨테이너가 안 떠 있음 | `docker compose up -d`, `docker compose ps` |
| 5432 포트가 이미 사용 중 | Mac에 PostgreSQL이 따로 설치돼 실행 중 | `brew services stop postgresql` 또는 `compose.yaml`의 포트를 `"15432:5432"`로 바꾸고 `application-local.yml` URL도 `15432`로 |
| `Validate failed: Migration checksum mismatch` | 이미 적용한 V 파일을 수정함 | 로컬이면 `docker compose down -v`로 초기화. 공유된 파일이면 수정을 되돌리고 새 V 파일로 |
| `Schema-validation: missing column [...]` | 엔티티 필드와 테이블 컬럼이 다름 | 오류에 나온 이름으로 엔티티 `@Column` 또는 마이그레이션 수정 |
| 테스트에서 `Could not find a valid Docker environment` | Docker가 꺼져 있음, 또는 OrbStack·Colima 소켓 경로 | Docker 앱 실행. Colima라면 `DOCKER_HOST`와 `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE` 설정 (Testcontainers 문서 참고) |
| Lombok 어노테이션이 빨간 줄 | 어노테이션 처리 꺼짐 | 3장의 3번 설정 |
| `Unsupported class file major version` / 툴체인 오류 | Gradle이 다른 JDK를 사용 | IntelliJ Gradle JVM을 21로, 터미널은 `java -version` 확인 |

## 7. 레포 구조

```text
BE-nerdnam/
├── build.gradle.kts                 # 의존성·Java 21 툴체인
├── settings.gradle.kts
├── gradlew, gradle/wrapper/         # Gradle Wrapper (9.8.1)
├── compose.yaml                     # 로컬 PostgreSQL(pgvector), Redis
├── docs/                            # 이 문서들
└── src/
    ├── main/java/com/nerdnam/
    │   ├── NerdnamApplication.java
    │   ├── member/  skill/  profile/  project/  jd/  matching/  guide/  rag/  aijob/   # 모듈 (package-info.java에 역할 설명)
    │   ├── feedback/  library/      # 만족도 평가, 라이브러리·온보딩 조회
    │   ├── infra/ai/                # AI 서버 클라이언트 (부패 방지 계층)
    │   └── common/                  # BaseTimeEntity, 오류 응답
    ├── main/resources/
    │   ├── application.yml          # 공통 설정
    │   ├── application-local.yml    # 로컬 DB 접속, SQL 로그
    │   └── db/migration/            # V1 스키마, V2 기술 사전 시드, V3 만족도 평가
    └── test/java/com/nerdnam/
        ├── TestcontainersConfiguration.java   # 테스트용 PostgreSQL+pgvector 컨테이너
        ├── NerdnamApplicationTests.java       # Flyway·pgvector 통합 테스트
        ├── support/ApiTestSupport.java        # API 통합 테스트 공통 부모 (AI 작업을 바로 실행)
        ├── architecture/ModuleBoundaryTest.java # 모듈 경계·순환 의존 검사
        └── <모듈>/...                          # 도메인 단위 테스트, API 테스트
```

## 8. 첫 커밋

레포가 아직 비어 있으므로(커밋 없음) 셋업 확인 뒤 첫 커밋을 만듭니다.

```bash
git add .
git commit -m "chore: Spring Boot 프로젝트 골격, 초기 스키마, 설계 문서"
git push -u origin main
```

`.gitignore`에 `build/`, `.gradle/`, `.idea/`, `.DS_Store`, 로컬 비밀값 파일이 이미 들어 있습니다. 비밀번호·API 키는 커밋하지 않고, 필요해지면 환경 변수나 `application-secret.yml`(커밋 제외)로 넣습니다.
